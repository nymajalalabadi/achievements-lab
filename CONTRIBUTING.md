# Contributing

Thanks for taking the time to contribute. This document describes the small set of conventions used in this repository.

## Branches

Always branch from main. Use a short prefix that says what kind of change it is, for example docs/, feat/, fix/ or chore/, followed by two or three words: docs/expand-readme, fix/null-check-on-load.

## Commits

Write the subject line in the imperative mood and keep it under about seventy characters. Explain the reason for the change in the body when the reason is not obvious from the diff.

## Pull requests

Keep pull requests small enough that a reviewer can read them in one sitting. Describe the problem first, then the solution, then anything a reviewer should pay extra attention to. Link the issue the pull request closes so it is closed automatically on merge.

## Reviews

Review the change, not the person. Prefer questions over commands, and mark comments as blocking only when they really are.
